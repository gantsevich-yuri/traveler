# ✈️ flights-monitor

Бот, который по расписанию ищет дешёвые авиабилеты (по умолчанию Москва → Таиланд) и присылает **топ лучших вариантов** в Telegram: в личку, группу или канал.

Работает в Docker, запускается одной командой. Данные о ценах берёт из официального API Travelpayouts (партнёрка Aviasales), ссылки в сообщениях ведут на aviasales.ru.

## Как это работает

```
┌──────────────────────── контейнер (работает постоянно) ────────────────────────┐
│                                                                                │
│   python monitor.py                                                            │
│                                                                                │
│   большую часть времени спит и ждёт ближайшего слота из SCHEDULE               │
│                                                                                │
│   в назначенное время:                                                         │
│     1. GET  api.travelpayouts.com  → цены по каждому направлению и месяцу      │
│     2. фильтры: окно дат, мин. длительность отпуска, пересадки, бюджет         │
│     3. сортировка по цене, берётся топ MAX_VARIANTS                            │
│     4. сверка с /data/seen.json (что уже отправляли)                           │
│     5. POST api.telegram.org/sendMessage → один дайджест в чат                 │
│     6. снова сон до следующего слота                                           │
│                                                                                │
└────────────────────────────────────────────────────────────────────────────────┘
```

Ключевые моменты:

- **Контейнер живёт постоянно**, но почти всё время спит: около 30 МБ памяти, CPU не нагружает.
- **Сайт aviasales.ru не парсится.** Запросы идут в API Travelpayouts. Капч и банов нет, нагрузки на сайт нет.
- **Сообщение приходит, только если в топе появился новый или подешевевший вариант.** Если всё то же, что вы уже получали, бот молчит (в логе будет запись).
- **Все настройки лежат в `.env`.** Код менять не нужно.

## Важные ограничения

Прочитайте до запуска, чтобы не было неожиданностей.

| Ограничение | Пояснение |
|---|---|
| **Цены из кэша** | Data API Travelpayouts отдаёт кэш поисков пользователей Aviasales.ru и Jetradar за последние ~48 часов. Цена может отличаться от актуальной, по редким датам и направлениям данных может не быть. Реальную цену покажет страница Aviasales по ссылке. |
| **Цена за одного взрослого** | Цены указаны за одного взрослого, эконом-класс. |
| **Одна авиакомпания** | API отдаёт одного основного перевозчика на билет, раздельно «туда» и «обратно» его узнать нельзя. |
| **Нет длительности пересадок** | Есть число пересадок и общее время в пути (вместе с пересадками). Время ожидания в каждой пересадке и аэропорты пересадок есть только в другом API (Flights Search API), к которому нужен отдельный доступ у Travelpayouts. |
| **Лимит ответа** | За один запрос API отдаёт ограниченное число записей (`API_LIMIT`, по умолчанию 1000). Если упрётся в лимит, в логе будет предупреждение. |

## Быстрый старт

### Что нужно

- Сервер, ноутбук или Raspberry Pi с установленными **Docker** и **Docker Compose v2** (команда `docker compose`, не `docker-compose`).
- Аккаунт в Telegram.
- Бесплатный аккаунт в Travelpayouts.

Проверка:

```bash
docker --version
docker compose version
```

### Шаг 1. Создать Telegram-бота

1. В Telegram откройте **@BotFather** и отправьте `/newbot`.
2. Придумайте имя и username (должен заканчиваться на `bot`).
3. BotFather пришлёт **токен** вида `123456789:AAH...`. Это значение для `TG_TOKEN`.

### Шаг 2. Узнать `TG_CHAT_ID`

Куда слать сообщения, выберите один вариант.

| Куда | Что сделать |
|---|---|
| **Личка** | Откройте своего бота и нажмите **Start** (или отправьте `/start`). Иначе бот не сможет вам писать. |
| **Группа** | Создайте группу, добавьте бота, напишите в группе любое сообщение. |
| **Канал** | Создайте канал, добавьте бота **администратором** с правом публикации, опубликуйте любой пост. |

Затем откройте в браузере (подставьте свой токен):

```
https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
```

Найдите в ответе блок `"chat":{"id": ...}`. Это число и есть `TG_CHAT_ID`:

- личка: положительное число, например `123456789`;
- группа и канал: отрицательное, обычно `-100xxxxxxxxxx`.

> Если `getUpdates` возвращает пустой список (`"result":[]`), напишите в чат ещё одно сообщение и обновите страницу. Для канала также можно использовать `@username_канала`.

### Шаг 3. Получить токен Travelpayouts

1. Зарегистрируйтесь на [travelpayouts.com](https://www.travelpayouts.com) (бесплатно).
2. Откройте раздел **Инструменты → API** и скопируйте **API token**. Это значение для `TP_TOKEN`.
3. (Необязательно) Скопируйте свой партнёрский **marker**: ссылки в сообщениях будут партнёрскими. Это значение для `TP_MARKER`.

### Шаг 4. Скачать проект и настроить

```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ> flights-monitor
cd flights-monitor
cp .env.example .env
nano .env        # или любой редактор
```

Минимум, который нужно заполнить в `.env`:

```env
TG_TOKEN=123456789:AAH...
TG_CHAT_ID=-100123456789
TP_TOKEN=ваш_токен_travelpayouts

ORIGIN=MOW
DESTINATIONS=HKT:1/2,BKK:1
DATE_FROM=2027-02-05
DATE_TO=2027-02-23
MIN_DAYS=12
BUDGET=70000
```

### Шаг 5. Запустить

```bash
docker compose up -d --build
docker compose logs -f flights
```

Через несколько секунд в логе появятся строки `started: ...` и `расписание: ...`. Если вариантов в бюджете нашлось, в Telegram придёт первое сообщение: при `RUN_ON_START=true` бот делает один прогон сразу при старте.

Выйти из просмотра логов: `Ctrl+C` (контейнер продолжит работать).

### Шаг 6. Проверить

```bash
docker compose ps
```

В колонке `STATUS` должно быть `Up ... (healthy)`.

> Если сообщение не пришло и лог говорит «Ничего не найдено», это не ошибка: в кэше нет билетов под ваши критерии. Временно поднимите `BUDGET`, расширьте даты или ослабьте лимит пересадок (см. [Решение проблем](#решение-проблем)).

### `requirements.txt`

```
requests==2.32.3
tzdata
```

### `Dockerfile`

```dockerfile
FROM python:3.12-slim

ENV PYTHONUNBUFFERED=1 PYTHONDONTWRITEBYTECODE=1

RUN useradd -r -u 10001 app && mkdir /data && chown app /data

WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY monitor.py .

USER app
VOLUME /data
CMD ["python", "monitor.py"]
```

### `compose.yaml`

```yaml
services:
  flights:
    build: .
    image: flights-monitor:latest
    container_name: flights-monitor
    restart: unless-stopped
    env_file: .env
    environment:
      STATE_FILE: /data/seen.json
      HEARTBEAT_FILE: /tmp/heartbeat
    volumes:
      - flights_data:/data
    healthcheck:
      # unhealthy, если успешной активности не было больше ~2 часов
      test: ["CMD", "python", "-c",
             "import os,sys,time; sys.exit(0 if time.time()-os.path.getmtime('/tmp/heartbeat')<7500 else 1)"]
      interval: 5m
      timeout: 10s
      retries: 1
      start_period: 90s
    read_only: true
    tmpfs:
      - /tmp
    cap_drop: [ALL]
    security_opt:
      - no-new-privileges:true
    mem_limit: 128m
    logging:
      driver: json-file
      options:
        max-size: "5m"
        max-file: "3"

volumes:
  flights_data:
```

> **Часовой пояс** (`TZ`) задаётся в `.env`, а не в `compose.yaml`. Если указать его в обоих местах, значение из `compose.yaml` перекроет `.env`, и расписание будет срабатывать в неожиданное время.

## Все переменные окружения

Задаются в файле `.env`. После изменения примените настройки:

```bash
docker compose up -d --force-recreate
```

### Секреты (обязательные)

| Переменная | Обязательна | По умолчанию | Описание | Пример |
|---|---|---|---|---|
| `TG_TOKEN` | да | — | Токен бота от @BotFather | `123456789:AAH...` |
| `TG_CHAT_ID` | да | — | ID чата, группы или канала | `-100123456789` |
| `TP_TOKEN` | да | — | API-токен Travelpayouts | `a1b2c3...` |
| `TP_MARKER` | нет | пусто | Партнёрский ID Travelpayouts. Если задан, он добавляется к ссылкам | `123456` |

### Что искать

| Переменная | Обязательна | По умолчанию | Описание | Пример |
|---|---|---|---|---|
| `ORIGIN` | нет | `MOW` | IATA-код города вылета | `MOW`, `LED`, `KZN` |
| `DESTINATIONS` | нет | `BKK:1/1,HKT:1/2` | Направления и лимит пересадок для каждого. [Синтаксис](#синтаксис-destinations) | `HKT:1/2,BKK:1,CNX` |
| `DATE_FROM` | **да** | — | Начало окна отпуска, включительно (`ГГГГ-ММ-ДД`). Вылет не раньше этой даты | `2027-02-05` |
| `DATE_TO` | **да** | — | Конец окна отпуска, включительно. Возвращение не позже этой даты | `2027-02-23` |
| `MIN_DAYS` | да, если `DATE_FROM` < `DATE_TO` | — | Минимальная длительность поездки в днях (включая день вылета и возвращения: 10→17 февраля = 8 дней) | `12` |
| `MAX_VARIANTS` | нет | `10` | Сколько самых дешёвых вариантов показывать в сообщении | `10` |
| `CURRENCY` | нет | `rub` | Валюта цен: `rub`, `eur`, `usd` | `rub` |
| `BUDGET` | нет | `40000` | Максимальная цена за одного человека в валюте `CURRENCY`. Всё дороже отбрасывается | `70000` |
| `MAX_PRICE` | нет | — | Старое имя `BUDGET`, работает, если `BUDGET` не задан | `70000` |
| `API_LIMIT` | нет | `1000` | Сколько записей запрашивать у API за раз. Если API отвечает ошибкой 400, уменьшите (например, до `300`) | `1000` |

### Расписание

| Переменная | Обязательна | По умолчанию | Описание | Пример |
|---|---|---|---|---|
| `SCHEDULE` | нет | пусто | Часы запуска через запятую: `ЧЧ` или `ЧЧ:ММ`. `24` = полночь. Если пусто, используется `INTERVAL_SEC` | `8,12,16,20,24` или `8:30,13,20:15` |
| `TZ` | нет | `UTC` | Часовой пояс для `SCHEDULE` (формат IANA) | `Europe/Moscow` |
| `RUN_ON_START` | нет | `true` | Делать ли один прогон сразу при старте контейнера. `false`: ждать ближайшего слота | `true` |
| `RETRY_SEC` | нет | `600` | Через сколько секунд повторить попытку после сбоя, не дожидаясь следующего слота | `600` |
| `INTERVAL_SEC` | нет | `3600` | Интервал между запусками в секундах. Работает только если `SCHEDULE` пуст | `3600` |
| `JITTER_SEC` | нет | `0` | Случайная добавка (0…N секунд) к каждому ожиданию | `300` |

### Поведение и уведомления

| Переменная | Обязательна | По умолчанию | Описание | Пример |
|---|---|---|---|---|
| `NOTIFY_EMPTY` | нет | `false` | Присылать в Telegram одно сообщение «ничего не найдено». Повторяется, только если варианты сначала появились, потом пропали | `true` |
| `SEEN_TTL_SEC` | нет | `604800` (7 дней) | Сколько хранить запись об отправленном варианте. По истечении он может прийти снова | `604800` |
| `SITE_URL` | нет | `https://www.aviasales.ru` | Домен, к которому добавляется путь поиска из ответа API | `https://www.aviasales.com` |
| `NAMES` | нет | пусто | Свои названия городов и аэропортов: `КОД:Название` через запятую | `KBV:Краби,DMK:Бангкок (Дон Муанг)` |
| `AIRLINE_NAMES` | нет | пусто | Свои названия авиакомпаний: `КОД:Название` через запятую | `XW:NokScoot` |
| `DEBUG_TICKET` | нет | `false` | `true`: в лог пишется сырой билет из API (для диагностики полей) | `false` |

### Служебные (уже заданы в `compose.yaml`, менять обычно не нужно)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `STATE_FILE` | `/data/seen.json` | Файл с историей отправленных вариантов (в volume) |
| `HEARTBEAT_FILE` | `/tmp/heartbeat` | Файл-метка для healthcheck |

## Синтаксис DESTINATIONS

Формат одного элемента: **`КОД:туда/обратно`**, элементы разделяются запятыми. Число после двоеточия означает **максимум пересадок**.

| Запись | Значение |
|---|---|
| `HKT` | Пхукет, пересадки не ограничены |
| `HKT:2` | Пхукет, до 2 пересадок и туда, и обратно |
| `HKT:1/2` | Пхукет, туда до 1 пересадки, обратно до 2 |
| `HKT:0` | Пхукет, только прямые рейсы в обе стороны |
| `HKT:0/2` | Туда только прямой, обратно до 2 пересадок |
| `HKT:1/` | Туда до 1 пересадки, обратно без ограничений |
| `HKT:/2` | Туда без ограничений, обратно до 2 |

Пример с несколькими направлениями:

```env
DESTINATIONS=HKT:1/2,BKK:1,CNX:0/2,USM
```

Здесь: Пхукет (1 туда / 2 обратно), Бангкок (по 1), Чиангмай (прямой туда / 2 обратно), Самуи (без ограничений).

> Лимит на обратный рейс применяется только в режиме «туда-обратно». При поиске в одну сторону берётся первое число.
> Опечатка (`HKT:one`, `HKT:-1`) остановит контейнер с понятным сообщением в логе.

### Коды популярных направлений

| Код | Город | Код | Город |
|---|---|---|---|
| `BKK` | Бангкок | `USM` | Самуи |
| `HKT` | Пхукет | `KBV` | Краби |
| `CNX` | Чиангмай | `UTP` | Паттайя (У-Тапао) |
| `DPS` | Бали | `SGN` | Хошимин |
| `CXR` | Нячанг | `PQC` | Фукуок |

Коды городов вылета: `MOW` Москва (все аэропорты), `LED` Санкт-Петербург, `KZN` Казань, `SVX` Екатеринбург, `OVB` Новосибирск, `KRR` Краснодар.

## Режимы поиска

Режим определяется автоматически по `DATE_FROM` и `DATE_TO`.

| Режим | Условие | Что ищется | `MIN_DAYS` |
|---|---|---|---|
| **Туда-обратно в окне отпуска** | `DATE_FROM` < `DATE_TO` | Вылет не раньше `DATE_FROM`, возвращение не позже `DATE_TO`, длительность не меньше `MIN_DAYS`. Из всех комбинаций выбираются самые дешёвые | обязателен |
| **В одну сторону** | `DATE_FROM` = `DATE_TO` | Билеты в одну сторону на эту дату | не нужен |

Пример: окно `05.02–23.02`, `MIN_DAYS=8`. Скрипт сравнит варианты вроде 10→17 февраля и 12→19 февраля и поднимет в топ тот, что дешевле. Варианты короче 8 дней отбрасываются.

## Расписание

Два способа задать частоту запросов.

**1. По часам (рекомендуется):**

```env
SCHEDULE=8,12,16,20,24
TZ=Europe/Moscow
```

Запуск в 00:00, 08:00, 12:00, 16:00 и 20:00 по московскому времени. Переход на летнее время учитывается автоматически.

**2. По интервалу:**

```env
SCHEDULE=
INTERVAL_SEC=3600
JITTER_SEC=300
```

Запуск каждый час плюс случайные 0–5 минут.

**При сбое** (нет сети, ошибка API) бот не ждёт следующего слота, а повторяет попытку через `RETRY_SEC`. После 3 неудач подряд в Telegram приходит предупреждение `⚠️ flights-monitor: 3 ошибки подряд, смотри логи`.

> Кэш Aviasales обновляется не мгновенно, поэтому запросы чаще нескольких раз в день почти ничего не добавляют.

## Как читать логи

```bash
docker compose logs -f flights
```

| Запись в логе | Что значит |
|---|---|
| `started: ...` | Контейнер стартовал, показаны применённые настройки. **Проверьте, что они ваши** |
| `расписание: 00:00, 08:00, ... (Europe/Moscow)` | Расписание и часовой пояс разобраны |
| `HKT вылет 2027-02, возврат 2027-02 (...): подходит по датам N, отсеяно по пересадкам M` | Запрос выполнен. `N`: билетов в нужном окне и нужной длительности, `M`: из них отсеяно по лимиту пересадок |
| `Ничего не найдено по заданным критериям` | Под фильтры (даты, бюджет, пересадки) ничего не подошло. Это не ошибка |
| `Новых вариантов нет, в топе те же N, что уже отправлялись` | Подходящие билеты есть, но вы их уже получали. Сообщение не отправлено |
| `sent digest: N вариантов, из них новых/подешевевших K` | Сообщение отправлено |
| `следующий запуск: ...` | Когда бот проснётся в следующий раз |
| `ответ упёрся в лимит 1000` | API вернул максимум записей, часть билетов могла не попасть в анализ |
| `у N билетов нет поля return_transfers` | В ответе нет данных о пересадках обратно, лимит к таким билетам не применён |
| `run failed (N in a row)` + traceback | Ошибка прогона. Подробности в traceback |

## Где хранится состояние и как его сбросить

Информация об уже отправленных вариантах хранится в файле **`/data/seen.json` внутри контейнера**. Это словарь «ключ билета → цена и время отправки». Файл лежит в Docker volume `flights_data`, поэтому переживает перезапуск и пересборку контейнера.

- **Ключ билета:** `ORIGIN-DEST-дата_вылета-дата_возврата`.
- **Когда присылать снова:** вариант новый или стал дешевле, чем в прошлый раз.
- **Срок жизни записи:** `SEEN_TTL_SEC` (7 дней), потом вариант может прийти повторно.

> Именованный volume получает префикс проекта, например `flights-monitor_flights_data`. Увидеть реальное имя: `docker volume ls | grep flights`.

### Как сбросить историю (получить топ заново)

Без пересоздания контейнера:

```bash
docker compose exec flights rm -f /data/seen.json
docker compose restart flights
```

С удалением volume:

```bash
docker compose down -v
docker compose up -d --build
```

> Просто `docker rm` контейнера volume **не удаляет**. Флаг `-v` у `docker compose down` удаляет его.

## Решение проблем

| Симптом | Причина | Решение |
|---|---|---|
| В логе `400 Bad Request ... destination=HKT%3A0%2F0` и `months=[...]` в строке `started` | Запущен **старый образ** со старым кодом | `docker compose build --no-cache && docker compose up -d --force-recreate`; проверить `grep DATE_FROM monitor.py` на хосте; удалить старые контейнеры (`docker ps -a`) |
| Контейнер падает, в логе `KeyError: 'TG_TOKEN'` (или `DATE_FROM`) | Не заполнена обязательная переменная | Проверить `.env`, он должен лежать рядом с `compose.yaml` |
| Контейнер падает с `Для окна DATE_FROM..DATE_TO задайте MIN_DAYS` | Окно дат задано, а `MIN_DAYS` нет | Добавить `MIN_DAYS` или поставить `DATE_FROM` = `DATE_TO` |
| `MIN_DAYS больше длины окна` | Минимальная поездка длиннее самого окна | Уменьшить `MIN_DAYS` или расширить окно |
| `Некорректное число пересадок в ...` | Опечатка в `DESTINATIONS` | Проверить [синтаксис](#синтаксис-destinations) |
| `Неизвестный часовой пояс TZ=...` | Неверное имя пояса | Использовать формат IANA, например `Europe/Moscow` |
| Telegram: `400 Bad Request: chat not found` | Неверный `TG_CHAT_ID` или бот не в чате | Перепроверить id через `getUpdates`, добавить бота в группу или канал |
| Telegram: `403 Forbidden` | Бот не может писать в личку или его удалили из чата | Нажать **Start** у бота; вернуть бота в группу; для канала сделать его администратором |
| Telegram: `401 Unauthorized` | Неверный `TG_TOKEN` | Скопировать токен из @BotFather заново |
| API: `HTTP 401/403` | Неверный `TP_TOKEN` | Перепроверить токен в кабинете Travelpayouts |
| API: `HTTP 400` на запросе с `limit` | Слишком большой `API_LIMIT` | Поставить `API_LIMIT=300` |
| Цены приходят не в рублях | Название параметра валюты в API может отличаться | В функции `get_tickets` заменить ключ `"currency"` на `"cy"` |
| Всегда «Ничего не найдено» | Нет билетов под критерии или данных в кэше | Поднять `BUDGET`, ослабить лимиты пересадок (`:2`, или убрать число), расширить окно, уменьшить `MIN_DAYS`. Включить `DEBUG_TICKET=true` и посмотреть сырой ответ |
| «Новых вариантов нет», хотя вы удалили контейнер | Volume с историей остался | См. [сброс состояния](#как-сбросить-историю-получить-топ-заново) |
| Расписание срабатывает в другое время | `TZ` задан в `compose.yaml` и перекрывает `.env` | Убрать `TZ` из `compose.yaml`, оставить в `.env` |
| `docker compose ps` показывает `unhealthy` | Больше ~2 часов подряд были сбои | Смотреть `docker compose logs flights`: причина в последних ошибках |
| `unknown flag` / `docker: 'compose' is not a docker command` | Старый Docker | Установить Docker Compose v2 |

Диагностика полей API: поставьте `DEBUG_TICKET=true`, перезапустите, и в логе появится строка `raw ticket: {...}` с реальным ответом API.

## Безопасность

- **Файл `.env` содержит секреты.** Он добавлен в `.gitignore`: не коммитьте его и не публикуйте скриншоты с токенами.
- Если токен бота утёк, перевыпустите его через @BotFather (`/revoke`).
- Контейнер работает без root, с `read_only`, `cap_drop: ALL` и `no-new-privileges`.
- Скрипт делает только исходящие HTTPS-запросы (Travelpayouts и Telegram). Открытых портов нет.
- Токен Travelpayouts лучше хранить в секрет-менеджере, если проект крутится не на домашнем хосте.

## FAQ

**Контейнер работает постоянно? Это не расточительно?**
Да, он постоянно запущен, но просыпается только по расписанию. Остальное время это один спящий процесс на ~30 МБ памяти.

**Почему бот молчит?**
Скорее всего, нет *новых* вариантов (см. логи: «Новых вариантов нет») или ничего не подходит под критерии. Молчание не значит поломку, если healthcheck зелёный.

**Можно искать несколько направлений сразу?**
Да, через запятую в `DESTINATIONS`. Топ формируется по всем направлениям вместе, самые дешёвые варианты идут первыми.

**Можно слать в канал?**
Да. Добавьте бота администратором канала, укажите `TG_CHAT_ID=-100...` или `@username_канала`.

**Можно запустить два независимых мониторинга (разные даты или маршруты)?**
Да: склонируйте проект в два каталога с разными `.env` и разным `container_name` в `compose.yaml` (volume у каждого проекта отдельный).

**Как перестать получать уведомления?**
`docker compose stop` (остановить) или `docker compose down` (удалить контейнер). После поездки не забудьте остановить: когда `DATE_TO` в прошлом, бот будет работать вхолостую.

**Почему цена в Telegram не совпала с ценой на сайте?**
Данные берутся из кэша, а сайт показывает актуальные. Разница нормальна. Если билет раскупили, ссылка запустит новый поиск.

**Это нарушает правила Aviasales?**
Нет: используется официальный партнёрский API Travelpayouts, а не парсинг сайта.
